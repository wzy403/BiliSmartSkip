如何运行测试和438回测
留在test-branch，从算法分支导出一个很小的临时源码目录即可，不需要再挂载工作树，
也不会占用VS Code分支。新克隆若还没有本地fix/improve-detction-rate分支，将下面
git archive中的分支名改为origin/fix/improve-detction-rate。以下在仓库根目录运行，全程离线：

BSS_CHECK_SOURCE=$(mktemp -d /private/tmp/bss-source.XXXXXX)
git archive fix/improve-detction-rate scr manifest.json | tar -x -C "$BSS_CHECK_SOURCE"
node eval/restore-content-inputs.cjs
node eval/content-benchmark.cjs check
BILISMARTSKIP_SOURCE_DIR="$BSS_CHECK_SOURCE/scr" node --test tests/*.test.cjs eval/*.test.cjs eval/*.test.mjs eval/labels/*.test.cjs eval/review/*.test.cjs
node eval/experiments/heatmap-full-20261004/verify-collection.cjs

输出路径可显式指定，避免重新回测覆盖受版本控制的历史实验报告。
不带新输出参数时，两个热度脚本仍兼容原来的默认文件路径。
本轮清理不修改广告算法或评分函数。

如何查看归档状态或恢复字幕采集过程文件
当前清单：eval/archives/extra300-acquisition-20261006-v2.json
清单保存原路径、大小、SHA-256、Git blob及storage状态：purged为27个已永久移除的
原视频，git为497个仍可恢复的字幕中间文件。sourceCommit仅记录改写前的来源提交，
不要求该旧提交仍存在，恢复工具直接读取未改变的字幕blob。
旧v1清单保持原字节，仅代表首轮清理时的历史状态，不能用它推断视频现在仍可恢复。
默认查看带storage状态的清单，不恢复任何文件：
node eval/restore-archived-evidence.cjs

验证497个保留的字幕对象，不写文件；27个原视频分别输出skipped-purged：
node eval/restore-archived-evidence.cjs --verify

仅确实要检查某次字幕采集时，再恢复具体一份，例如：
node eval/restore-archived-evidence.cjs --restore eval/labels/assistant-content-extra300/acquisition/subtitles-anonymous.jsonl

恢复全部497个字幕中间文件（约100MiB），明确跳过27个已永久移除的原视频：

恢复工具从本地Git读取，校验大小与SHA-256，不联网、不覆盖不同内容、不自动stage。
指定恢复一个purged原片会直接报“已永久移除”，不创建文件。如果日后要重新观看
原片，需要另行从其原始来源获取；测试、回测、截图和最终字幕均不需要恢复原片。
